# Fate

The next step is the text generator. Either a tracery templated thing or a markov chain from corpus or possibly a combination of both. This is fairly well-trod territory for me, I did both for a class with my MFA thesis advisor Allison Parrish, and a lot of markov chain text for my thesis project grotto. I am thinking maybe a combination of both, since I want it to kind of make sense but have a really wide range of variation so that it seems hopeless to figure out the connection between the sliders and the text output. It's funny though, a lot of the meaning of this project will come across in how the text is actually generated. If it was totally deterministic and really seeded by the slider values, it would be the same text each time the sliders were at the same value. This might communicate that the player has control of their character and therefore control of their fate, and fate is bound to character. If it's still random each time the sliders are at the same position, it seems like there's no connection between character and fate. I am wondering if there shouldn't be a random element outside of the player's control, like a randomly assigned name that they can't change, that is a confounding element. So even if the sliders are the same the random name makes it more difficult to test what's going on. Of course all of this is even more complicated by the fact that this is a *journaled, open repo project* so someone can actually look at the code and even these journal entries and see what is actually happening.

Ugh, this kind of thinking is paralyzing. It's working against the joke/idea. I need to give myself the freedom to at least imagine that there is a separation between the material of the project, the *Textons* and *Scriptons* if that is appropriate here. This is a game, and as a game it is theatrical. I propose that in my working definition of a digital game as opposed to "interactive art" there is both some kind of game self and that I get to put some kind of conceptual bubble... *a magic circle if you will* around the part that you play, even if all the guts are also exposed.

So. I feel like... the sliders should actually seed the text generation in some way. That's doable with markovify and spacy, I am pretty sure I've done it before. But that seed is basically useless because there will be some confounding random element that is outside of the players control. Why should I do this? why shouldn't it just be totally random if we are considering the code separately from the game? Welllll it's just some kind of gut feeling... that it will feel different, that I will still know whether it's totally random or whether the player is really doomed by something as arbitrary as hand wrinkles. I'm just going to have to feel my way through it, see what the text output is like and then decide.

In the meantime I think I am going to have to build up a corpus and template. I'll do it when I am safely through most of my weeks readings.
