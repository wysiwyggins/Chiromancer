How do people not just cuss a lot in annotated portfolio journals?

I realize now why Lauren was leery about svg in p5, I had forgotten that at it's core it's kind of machine barf, and that every svg editor does it's own version of machine barf, and it's a wonder that the same file opens in different apps. The only reason it appeals to me is that it's machine barf that will open in a browser like an image but that you can get your fingers dirty inside and style individual elements with CSS. Just taking that codepen example and torturing the path a little bit more in inkscape was brittle and a chore. I initially tried drawing a fun curly line freehand but there was no getting it free of the weird transforms and sizing needed to have it play nice with the original demo.

I can tell this is going to require a lot more tinkering.

[demo](./slip_slider/index.html)

Ok, here's why this is a bad method for doing this and why I should go another direction:

This method is like how we used to do fancy custom-styled html inputs back in the jQuery era (shiver)— basically you use css and a bunch of funky javascript to hide a normal input element and then make a fake one that feeds the clicks to the real input. It's an overly complicated way of building something because the main goal is keeping the regular html input element. You used to have to do this to make things like checkboxes look radically different than the default checkboxes because just messing with them in css wasn't enough, it was easier to make a totally new thing out of css and just hide the old one. Here we are adding event listeners to svg elements and then using map() to map those values over to the real hidden slider.

Do I really care about these using actual html range inputs though? Not really? I mean it's always cool if something can be done in a browser instead of a game engine, but surely I can just make something from scratch in a canvas that acts like a slider, and probably feels better too (this thing seems to stick a lot when you are dragging.)

This example has it's own map function though, called `map5()` (from the comment it looks like it's stolen from p5.js too.)

`n` — the input value we want to remap
`a`, `stop1` — the input range (min, max) that n currently lives in
`start2`, `stop2` — the output range you want to convert into
`withinBounds` — optional flag: if true, clamp the result so it can't overshoot the output range.

`var newval = (n - a) / (stop1 - a) * (stop2 - start2) + start2;`

uhhh...newval is a fraction of the input value over the input range from 0 to 1.

there's a bounds check...we are just using `m.x`...

Maybe why it feels sticky and kind of bad is because it's just mapping the x position and this svg path is irregularly diagonal. Once you grab it it ought to be listening to either x or y, probably.

Is it really important to have draggable slider controls at all? I could probably do the whole idea in 4 weeks if I just had a bunch of int value inputs for each line and then just updated the lines in the drawing based on that. It wouldn't be very game-feely though, you wouldn't feel like you were tracing your fingers over a hand reading their fate.

What is the most important thing I am trying to prototype here? Is it the slider, which seemed like a good first byte sized chunk that everything else depends on and which could be used to then scaffold into a bigger thing, or is it the whole joke of character = fate to the extreme? Is the joke interesting enough that you play with it mutltiple times without the novel input that gives you something to fiddle with in a "tactile" way? Randomized text makes it worth playing with mutiple times as you try to figure out what the relationship with the sliders is to the story that gets churned out.

Maybe the first version of this is regular range sliders that aren't hidden, but which directly hide and reveal lines on a hand. So you are still using a mapping between the two things but you are using the simplified control so that it doesn't feel clunky as you try to drag the handle across the irregular line. This will definitely change the feeling though, now you have an additional "control panel" which is like some kind of mad scientist thing where you are making/mutating the hand in order to proscribe its fate. I don't know what my opinion is of that conceptually but it's still funny? It maybe brings videogame character creation back into the prototype more clearly... Also it will probably be easier to do and, as I said, feel more responsive.
